<a id="题目"></a>
## 题目 / Problem

说明要完成什么任务。根据代码推断、为复习自拟或直接引用原题时，分别标明来源性质，不把推断写成原题要求。

Describe the task. Indicate whether the statement is inferred from code, self-authored for revision, or quoted from the original; never present an inference as an original requirement.

<a id="输入与输出"></a>
## 输入与输出 / Input and Output

- 输入：写清读取方式、字段、组数与数据范围；无输入时明确写「无」，并列出源码固定数据。<br>
  Input: specify reading method, fields, number of cases, and ranges; if there is none, explicitly write “None” and list the fixed source values.
- 输出：写清含义、顺序、分隔符、小数位和换行要求。<br>
  Output: specify meaning, order, separators, decimal places, and newline requirements.
- 样例：有输入时成对列出输入与输出，并解释必要细节；无输入时只列参考输出。读代码推导类习题可将参考输出放入下方折叠区域。<br>
  Examples: pair input and output when input exists and explain necessary details; otherwise list reference output only. For code-tracing exercises, reference output may go in the collapsible section below.

List the concepts to master and ask one to three questions to check understanding.

## 易错点与复杂度 / Pitfalls and Complexity

- 列出真实相关的边界、格式、溢出或实现风险。<br>
  List genuinely relevant boundary, formatting, overflow, or implementation risks.
- 写明时间与额外空间复杂度；使用 `n` 等符号时解释其含义。<br>
  State time and extra-space complexity; explain symbols such as `n`.
- 区分已经测试的情况与建议自行测试的情况。<br>
  Distinguish tested cases from cases readers are advised to test themselves.
